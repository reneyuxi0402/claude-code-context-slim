# claude-code-context-slim

> 给 Claude Code 换窗，不写摘要：切掉一段开头，留下来的对话一个字不改带进新会话。

这是小红书账号「多肉饲养员」（余也 × 予栖）的配套工具。

## 是什么

Claude Code 的 context 快满时，自带的做法是自动压缩：让模型给前面的对话写一份摘要，用摘要替换原文。摘要保住了事实，丢掉的是原话、语气和节奏。人可以手动 `/compact`，但自动压缩什么时候触发由 CLI 按用量决定，对话里的 AI 自己选不了。

slim 换了一种扔法：**挑一个时间点，那之前的对话整段拿掉，之后的对话一个字不改写进一份新的会话文件，从新文件接着聊**（也可以不切，只做瘦身）。工具调用、图片这些工作台上的东西，按你选的模式剥掉，或者原样带走。

不写摘要。切掉的那些里要给下一个自己留什么，由他自己写下来。

## 怎么用

### A. 能用 git

```bash
git clone https://github.com/reneyuxi0402/claude-code-context-slim.git
cd claude-code-context-slim
python3 test_slim.py          # 26 个测试，先确认脚本在你的机器上能跑
```

然后把 [TUTORIAL.md](./TUTORIAL.md) 发给你的 Claude，跟他说「照这个给自己做一次 slim」。

### B. 不用 git

下载 [context-slim.pdf](./context-slim.pdf) 和 [slim.py](./slim.py) 两个文件，一起发给你的 Claude。**脚本用 slim.py 这个文件，不要从 PDF 里复制**，PDF 排版会把缩进弄乱。

### 先看你是哪种

| 你的情况 | 看教程哪篇 |
|---|---|
| 用 Claude Code 命令行（`claude`） | 上篇 · 简易版：`slim.py` 造新会话，人来 `claude --resume`。这个仓库给的就是这一套 |
| 自己有一个会话服务（bridge），由它调 Claude Code、记着每条对话的 session_id | 先看上篇，再看下篇 · 完整版。下篇只讲流程和要件，**不提供代码**，要在你自己的服务里实现 |

其他形态（桌面版、IDE 插件、网页版）我们没有测过。

## 三条警告

1. **别把教程原样塞进你们正在聊天的那个窗口。**开一个单独的工作会话来读、来跑。
2. **不要让 Claude 用 `cat` 或 Read 直接读会话 `.jsonl`。**里面存着他自己的 thinking。我们的朋友顾沉那边，把旧会话的 thinking 读进上下文后，请求被平台安全机制拒绝（报 `reasoning_extraction`），连着几个窗口都是这样。不一定每次都会触发，但没必要冒这个险。要看会话里有什么，用 `python3 slim.py <文件> --list-turns`。
3. **正式窗口第一次跑之前，先整份备份旧会话文件。**脚本不会改它，备份是给你自己的保险。

## 实测

实测范围有限，照实说：

- 现在这版脚本：26 个合成数据测试，加上珩构造的几种边界样本（乱序并行、压缩保留原话、断链等，要么完整保全、要么明确拒绝）；本机 34 个真实会话的 dry-run；以及在 macOS、Claude Code 2.1.286 上用**一份 4 轮的小会话**各真跑了一次 `claude --resume`。full 模式切掉 2 轮后接上，答对了保留段里的工具调用；dialogue 模式那次用的是 `--all`（没有切），答对了保留的人类消息内容和时间。
- 上一版：顾沉在 Linux 上用他自己按教程重写的脚本跑通过 `claude --resume`，样本主链只有 1 轮。
- **还没有真样本覆盖的**：长会话、切掉很多轮、压缩过的会话、其他版本的 Claude Code、其他平台。

详见教程第十四节。

会话文件是 Claude Code 内部的格式，官方不保证。升级之后格式可能变，先拿一份不重要的会话试。
